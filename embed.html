Embedding Ali Maps

One <iframe>. The map draws and routes entirely in the visitor's browser against static files — there is no API key, no request to us per view, and nothing to rate-limit.

The snippet

<iframe></iframe>

Parameters

NameMeaning
fcorpus (default) or osm. Which map.
embed1 hides the controls. A framed page is treated as embedded anyway.
lat, lonOpen on a place rather than fitting everything.
zHow many metres the view is across. Default 600.
from, tolat,lon each. Routes on load and fits the result.
kHow many distinct roads a snap may try. Default 1.

Embedding a route

An embed can carry the journey, so a page can link to the route it is writing about rather than to a map somebody has to drive themselves.

<iframe src="https://maps.ali-web-services.com/?f=osm&from=24.7136,46.6753&to=24.8894,46.6293"
        width="100%" height="420" style="border:0" loading="lazy"></iframe>

What the embed will not hide

Two things stay on screen whatever the parameters say. The OpenStreetMap attribution, because the basemap tiles are visible and their licence requires it wherever they are shown. And the provenance badge: the Riyadh flavour is a tech demo built from imported OpenStreetMap geometry, the corpus flavour is road we detected from imagery ourselves, and the two must never be mistaken for one another — including in a screenshot of somebody else's page.

Status

In development. The corpus covers three districts of Riyadh and is sparse on purpose: it holds only road we have detected, with no network imported from anywhere at any stage. Routes that fail are reported as failures rather than quietly redrawn, and road we can draw but cannot route on is shown in pink.
